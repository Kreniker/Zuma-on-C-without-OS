# Zuma для UEFI x64

## Сборка

Запустите из корня проекта в PowerShell 5.1 или новее:

```powershell
.\uefi\build.ps1
```

Требования: Windows, Visual Studio 2022 с компонентом C++ x64/x86 tools,
заголовки `MdePkg` из EDK II. Скрипт ищет их в соседних проектах, в `EDK2_PATH`
либо использует параметр `-Edk2`. BaseTools, NASM, SDL2, Expat и BASS для этой
сборки не требуются. `System.Drawing` из Windows преобразует изображения.

```powershell
.\uefi\build.ps1 -Edk2 C:\src\edk2
# После изменения только C-кода, когда ресурсы уже подготовлены:
.\uefi\build.ps1 -SkipAssets
```

Выходной каталог по умолчанию — `build-uefi`, другой задаётся через `-OutDir`.
Сборка не изменяет соседние EDK II-проекты и не скачивает зависимости.

## Комплект для запуска

```text
build-uefi/esp/
  EFI/BOOT/
    BOOTX64.EFI
    settings.txt
    images/...png.ztex, ...jpg.ztex
    fonts/...png.ztex, ...txt
    levels/levels.xml, ...dat, ...jpg.ztex, ...png.ztex
```

Копируйте содержимое `esp` целиком на FAT32-носитель. Приложение ищет ресурсы
относительно собственного `.efi`, независимо от рабочего каталога UEFI Shell.
Настройки и `progress.bin` сохраняются рядом с ним; для сохранений нужен
доступ на запись. Можно переименовать или переместить `.efi`, сохранив рядом
все ресурсы. По стандартному пути `EFI\BOOT\BOOTX64.EFI` его можно загрузить
через меню UEFI как приложение со съёмного носителя.

Сборка предназначена для **x64 UEFI** с GOP. IA32, ARM64 и Legacy BIOS не
поддерживаются. Файл не подписан для Secure Boot. Для проверки используйте
OVMF без Secure Boot или загрузку с отключённым Secure Boot.

## Управление

| Действие | Мышь | Клавиатура |
|---|---|---|
| Переместить курсор / прицел | Движение | Стрелки, WASD |
| Выбрать / выстрелить | Левая кнопка | Enter, пробел |
| Сменить шар | Правая кнопка | X |
| Завершить приложение | Exit в меню | Esc |

Используются Simple Pointer и Absolute Pointer, если прошивка их предоставляет.
Клавиатура позволяет играть и при отсутствии поддержки мыши в UEFI.

## QEMU / OVMF

С установленным QEMU и прошивкой OVMF:

```powershell
.\uefi\run-qemu.ps1 -Qemu 'C:\Program Files\qemu\qemu-system-x86_64.exe' `
  -Firmware 'C:\Program Files\qemu\share\edk2-x86_64-code.fd' `
  -Vars 'C:\Program Files\qemu\share\edk2-i386-vars.fd'
```

Скрипт использует готовый `esp` и 512 МБ RAM. Через `qemu-img.exe` он один
раз создаёт отдельный FAT-образ `build-uefi\Zuma.img`; рекорды виртуальной
машины сохраняются в этом образе. `qemu-img.exe` ищется рядом с QEMU или
задаётся параметром `-QemuImg`. Можно передать готовый `-DiskImage`.
После изменения сборки `-RefreshImage` заново создаёт образ из `esp`,
**удаляя сохранения внутри старого образа**.

Параметр `-Vars` необязателен,
но при наличии файла берётся его отдельная копия для виртуальной машины.
Код и VARS должны быть из одного комплекта прошивки. Отдельный образ также
позволяет проверять сохранения без ограничений записываемого vvfat-каталога.

## Проверки

С Python 3 и Windows SDK для сборки тестовой DLL:

```powershell
.\uefi\tests\test.ps1 -Python python
```

Тесты проверяют PE32+, архитектуру x64, UEFI subsystem, отсутствие импортов
ОС и наличие перемещений; все 63 текстуры и кривые 18 игровых уровней.
Настоящий C-парсер сравнивается с Python ElementTree на `levels.xml` при
разных размерах входных порций, а также проверяется на повреждённом XML.
Загрузчик игры проверяется вместе с записью и чтением рекорда. Сохранения
тестов создаются в отдельной временной папке.

В загрузчике этапов добавлена проверка границ: исходный XML описывает
13 этапов, тогда как игра использует один этап из 18 доступных уровней.

## Устройство порта

- `Entry.c`: точка входа `EfiMain`, загрузочный том, протоколы UEFI,
  восстановление исходного графического режима при выходе.
- `Graphics.c`: используемая игрой часть SDL API, программные текстуры,
  поворот, прозрачность, масштабирование с сохранением пропорций, курсор и ввод.
- `Runtime.c`: выделение памяти через Boot Services, буферизованные файлы
  через Simple File System, нужные игре функции C и математики. Время измеряется
  через TSC с калибровкой при старте; целевая платформа — обычный x64 PC.
- `Format.c`: форматирование строк, включая ширину счёта и ведущие нули таймера.
- `Xml.c`: небольшой парсер **только для формата игровых ресурсов**:
  элементы, атрибуты, комментарии и пять стандартных XML-сущностей.
  Это не полноценный Expat; DTD и внешние сущности не поддерживаются.
- `prepare-assets.ps1`: PNG/JPEG → `.ztex`. Заголовок: три little-endian
  `uint32` (сигнатура `0x58544d5a`, ширина, высота), затем BGRA8 сверху вниз.
  Исходные изображения сохраняются в `content` без изменений.

В игре сохранены меню, уровни и механика. Звук отключён: в стандартном UEFI
нет универсального аудиовыхода, а исходные BASS DLL требуют ОС. Рендеринг
программный, поэтому скорость зависит от CPU и реализации GOP. Игровой код
исходного проекта привязывает часть движения к кадрам; при низкой частоте
кадров игровой процесс будет медленнее.

Общие исправления: вынесены определения глобальных переменных из заголовков,
исправлены выход за массив рекордов, размер XML-буфера при чтении, чтение
заголовка сохранений, запись `int` в `bool` при загрузке настроек, буфер
kerning-пар шрифта, неинициализированный цвет шара и коды возврата загрузки.

Справочные документы: [UEFI GOP и протоколы ввода](https://uefi.org/specs/UEFI/2.10/12_Protocols_Console_Support.html),
[MSVC EFI_APPLICATION](https://learn.microsoft.com/en-us/cpp/build/reference/subsystem-specify-subsystem?view=msvc-170).
